## 4. 🚨 العيوب الجديدة أو المتبقية الأهم

### T01 — حرج: الإزالة قد تحذف النسخ الاحتياطية رغم تعليمها protected

**المواضع:** `app/services/uninstall_service.py`، discover_installation نحو السطر 300 وexecute_item نحو 598–606.

الاكتشاف يضيف مجلد التثبيت الأب كعنصر غير محمي، ثم يضيف backups تحته كعنصر محمي مستقل. التنفيذ يفحص حماية الأب فقط ثم ينفذ shutil.rmtree للأب؛ لا يستثني الأبناء المحميين. لذلك تعليم الطفل protected لا يمنع حذفه ضمن الأب.

**المطلوب:** منع الحذف التكراري لأي أب يحوي محتوى محمياً أو إنشاء خطة حذف انتقائية تحافظ على تلك الفروع. هذه أولوية قبل استخدام Full Cleanup.

### T02 — عالٍ: pipeline الجديد يعلن تثبيت Odoo دون تثبيته

**الموضع:** `app/core/installation_pipeline.py`، تعريفات postgresql/odoo_install/traefik_install/jenkins_install و_run_component.

أوامر install/verify لهذه المكونات هي echo لاسم المرحلة. النجاح يعتمد على returncode، فيصبح المكون INSTALLED بعد طباعة النص فقط. المكونات الأخرى تحتوي فحوصاً مثل docker version || true أو inspect || echo unavailable، فتخفي الفشل أيضاً.

**المطلوب:** ربط المكونات بخدمات التثبيت الفعلية والتحقق من قاعدة البيانات وHTTP، وعدم إعطاء حالة installed لمرحلة placeholder.

### T03 — عالٍ: إصلاح اسم metadata أدخل متغيراً غير معرف

**الموضع:** `automation/scripts/restore-db.sh:42`، بينما التعريف عند 115.

META_FILE وFILESTORE_FILE يستخدمان DIRNAME مع set -u قبل `DIRNAME=$(dirname ...)`. تجربة السكريبت على ملف موجود وهمي أعادت DIRNAME: unbound variable قبل أي اتصال Docker.

**المطلوب:** تهيئة dirname عند قراءة الوسائط، قبل حساب الملفات المرافقة.

### T04 — عالٍ: إعدادات الاتصال الجديدة لا تصل إلى Odoo كما هو متوقع

**الموضع:** `app/core/server_setup.py`، أوامر docker run لإصدارات Odoo.

أُضيفت DB_HOST/DB_PORT/DB_USER/DB_PASSWORD. entrypoint الرسمي لـOdoo18 يقرأ HOST/PORT/USER/PASSWORD أو بدائل PG*، وليس هذه الأسماء. لذلك يستمر الاتصال بالافتراضات بدلاً من odoo17-db.

### T05 — عالٍ: استعادة MultiVersion ما زالت تقرأ ملف المضيف داخل الحاوية

**الموضع:** `deployment/Odoo-MultiVersion-Deployment/scripts/restore.sh:193`.

DB_FILE يمثل /data/backups/... على المضيف، لكن psql -f يعمل داخل الحاوية دون copy أو mount لهذا الملف.

### T06 — متوسط: تعذر فحص كل المكونات ينتج SUCCESS

**الموضع:** `app/core/server_setup.py`، _inspect_component/install_component/generate_report، خاصة نحو 680.

عند FileNotFoundError أو timeout تُصنف المكونات NOT_CHECKED ثم SKIPPED بسبب عدم الجاهزية. overall_success ينظر إلى failed/warnings فقط.

### T07 — متوسط: Paused يُفسر كخدمة تعمل

**الموضع:** `app/services/odoo_service.py:150` وما يماثله في Jenkins.

startswith('up') يحل Up العادي، لكنه يقبل `Up 2 hours (Paused)`.

### T08 — عالٍ: اكتشاف Odoo لا يزال يقبل الصور الخاطئة

**الموضع:** `app/services/odoo_service.py:46–62`.

شرط الاسم OR الصورة يجعل أي حاويتين باسم odoo17 وodoo17-db مقبولتين حتى لو كانتا nginx وredis.

### T09 — عالٍ: fallback المرفقات لا يطابق المستعيد

**الموضع:** `automation/scripts/backup-db.sh:74–80` و`restore-db.sh` قسم فك filestore.

المسار الأساسي يؤرشف DB_NAME، لكن fallback يؤرشف filestore الذي يحتوي قواعد متعددة.
