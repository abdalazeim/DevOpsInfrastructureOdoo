# 1. النتيجة النهائية

تم إعداد وتشغيل نسختين مستقلتين من نظام Odoo على خادم Ubuntu واحد باستخدام Docker وDocker Compose، مع استخدام Traefik لتوجيه الطلبات إلى كل نسخة حسب اسم النطاق.

| النظام | الإصدار | الرابط | الحالة |
|---|---|---|---|
| Odoo | 17 | http://odoo17.devops-odoo.com/ | ✅ يعمل |
| Odoo | 19 | http://odoo19.devops-odoo.com/ | ✅ يعمل |

### البنية التقنية

| المكون | التقنية المستخدمة |
|---|---|
| نظام التشغيل | Ubuntu |
| الحاويات | Docker |
| إدارة الحاويات | Docker Compose |
| Reverse Proxy | Traefik v3.7 |
| شبكة Docker المشتركة | proxy |
| قاعدة بيانات Odoo 17 | PostgreSQL 16 |
| قاعدة بيانات Odoo 19 | PostgreSQL 18 |

# 5. إعداد شبكة Docker المشتركة

تم اعتماد شبكة خارجية مشتركة باسم:

```text
proxy
```

الهدف منها تمكين Traefik من الاتصال بخدمات Odoo الموجودة في مشاريع Docker Compose مختلفة.

### التحقق من الشبكة

```bash
sudo docker network ls
```

### عرض تفاصيل الشبكة

```bash
sudo docker network inspect proxy
```

ملاحظة: أثناء العمل ظهرت رسالة تفيد بأن الشبكة موجودة مسبقاً. هذا ليس خطأً في النظام، ولا حاجة لإنشاء الشبكة مرة أخرى.

# 6. إعداد Traefik

تم استخدام:

```text
traefik:v3.7
```

### المنافذ

| المنفذ | الاستخدام |
|---|---|
| 80 | استقبال طلبات HTTP |
| 10090 | لوحة تحكم Traefik |
| 8080 | المنفذ الداخلي للوحة التحكم |

### مسؤوليات Traefik

1. استقبال طلبات المستخدمين.
2. تحديد اسم النطاق المطلوب.
3. توجيه الطلب إلى حاوية Odoo المناسبة.
4. العمل كـ Reverse Proxy.
5. فصل توجيه Odoo 17 عن Odoo 19.
6. تمكين تشغيل عدة أنظمة على خادم واحد.

### قواعد التوجيه

```text
Host(`odoo17.devops-odoo.com`)
          |
          v
      Odoo 17:8069
```

```text
Host(`odoo19.devops-odoo.com`)
          |
          v
      Odoo 19:8069
```

يجب التأكد من أن خدمات Odoo متصلة بشبكة `proxy`، وأن إعدادات Traefik تشير إلى منفذ Odoo الداخلي 8069.

# 7. معالجة مشكلة Odoo 19 – HTTP 502

### المشكلة

عند محاولة فتح نطاق Odoo 19 ظهرت رسالة:

```text
502 Bad Gateway
```

### التشخيص

تمت مراجعة إعدادات Docker Compose والاتصال بين Odoo وPostgreSQL.

تبين وجود عدم تطابق في كلمة مرور قاعدة البيانات، حيث كانت إحدى القيم التجريبية لا تطابق كلمة المرور الفعلية.

### خطوات المعالجة

1. مراجعة إعدادات خدمة PostgreSQL.
2. مراجعة إعدادات خدمة Odoo.
3. التأكد من تطابق بيانات الاتصال.
4. استخدام اسم خدمة قاعدة البيانات `db`.
5. إعادة إنشاء حاوية Odoo 19.

### الأمر المستخدم

```bash
cd /opt/odoo19-enterprise

sudo docker compose up -d --no-deps --force-recreate odoo19
```

### النتيجة

تم حل مشكلة الاتصال، وأصبح النطاق يعمل:

```text
http://odoo19.devops-odoo.com
```

# 8. معالجة مشكلة Odoo 17 – Connection Reset by Peer

### المشكلة

عند تنفيذ اختبار الاتصال:

```bash
curl -I http://localhost:10017/web/database/selector
```

ظهرت الرسالة:

```text
curl: (56) Recv failure: Connection reset by peer
```

كانت المشكلة أن خدمة Odoo لم تكن قد بدأت بشكل مستقر.

### المرحلة الأولى: فحص الحاويات

```bash
sudo docker ps -a
```

تمت مراجعة حالة الحاويات والتأكد من وجود حاوية Odoo وقاعدة البيانات.

### المرحلة الثانية: اكتشاف مشكلة PostgreSQL

تبين وجود عدم تطابق في كلمة مرور PostgreSQL بين خدمة Odoo وخدمة قاعدة البيانات.

تمت مراجعة إعدادات الاتصال والتأكد من القيم التالية:

| الإعداد | القيمة |
|---|---|
| Database Host | db |
| Database Port | 5432 |
| Database User | odoo |
| Database Name | postgres |

تم توحيد كلمة المرور بين الخدمتين.

### المرحلة الثالثة: اختبار الاتصال من داخل الحاوية

تم استخدام Python ومكتبة psycopg2 لاختبار الاتصال:

```bash
sudo docker exec odoo-17-docker-odoo17-1 python3 -c "import psycopg2; c=psycopg2.connect(host='db',port=5432,user='odoo',password='YOUR_PASSWORD',dbname='postgres'); print('DATABASE CONNECTION SUCCESS'); c.close()"
```

يجب استبدال `YOUR_PASSWORD` بكلمة المرور الفعلية دون مشاركتها.

### النتيجة

```text
DATABASE CONNECTION SUCCESS
```

وهذا أكد نجاح اتصال Odoo بقاعدة PostgreSQL.

# 9. معالجة تأخر تشغيل Odoo 17 داخل Entrypoint

بعد إصلاح اتصال PostgreSQL استمرت مشكلة تأخر ظهور خدمة Odoo.

تم فحص ملف:

```text
/opt/odoo-17-docker/entrypoint.sh
```

وتبين أنه ينفذ عدة خطوات عند بدء الحاوية.

### العمليات التي ينفذها الملف

| الترتيب | العملية |
|---|---|
| 1 | ترقية pip |
| 2 | تثبيت Python requirements |
| 3 | التحقق من تثبيت logrotate |
| 4 | تنفيذ apt-get update عند الحاجة |
| 5 | تثبيت logrotate |
| 6 | نسخ إعدادات logrotate |
| 7 | تشغيل cron |
| 8 | انتظار جاهزية PostgreSQL |
| 9 | تشغيل Odoo |

### السبب

كان الأمر:

```bash
apt-get update
```

يستغرق وقتاً بسبب تنزيل بيانات مستودعات Ubuntu.

خلال هذه الفترة لم يكن Odoo قد بدأ بعد، ولذلك كان الاتصال بالمنفذ 10017 يفشل.

### فحص العمليات داخل الحاوية

```bash
sudo docker exec odoo-17-docker-odoo17-1 sh -c 'ps aux | grep -E "apt-get|apt |odoo" | grep -v grep'
```

أثناء الفحص ظهر تنفيذ apt-get، وبعد انتهاء التثبيت ظهر تشغيل Odoo:

```text
/usr/bin/python3 /usr/bin/odoo
```

### التحقق من تثبيت logrotate

```bash
sudo docker exec odoo-17-docker-odoo17-1 dpkg -s logrotate 2>/dev/null | grep Status
```

النتيجة:

```text
Status: install ok installed
```

وهذا أكد أن logrotate تم تثبيته بنجاح.

# 13. تحسين مقترح لملف Entrypoint

أثناء التشخيص ظهر أن ملف Entrypoint يمكن تحسينه لتجنب تنفيذ تحديث apt غير الضروري عند كل تشغيل.

### أولاً: أخذ نسخة احتياطية

```bash
sudo cp /opt/odoo-17-docker/entrypoint.sh /opt/odoo-17-docker/entrypoint.sh.backup
```

### ثانياً: المقطع المقترح

```bash
if ! dpkg-query -W -f='${Status}' logrotate 2>/dev/null | grep -q "install ok installed"; then
    apt-get update
    DEBIAN_FRONTEND=noninteractive apt-get install -y logrotate
fi

pip3 install -r /etc/odoo/requirements.txt
```

### الهدف من التحسين

- عدم إعادة تثبيت logrotate إذا كان مثبتاً.
- عدم ترقية pip في كل مرة دون حاجة.
- تقليل وقت بدء الحاوية.
- تجنب التأخير غير الضروري عند إعادة تشغيل Odoo.

**ملاحظة:** هذا تحسين مقترح تمت مناقشته أثناء العمل، ولا يوجد تأكيد بأنه تم تطبيقه فعلياً.

# 14. تعليمات مهمة لحماية قواعد البيانات

⚠️ يجب الالتزام بالتعليمات التالية:

**1. لا تستخدم الأمر التالي دون التأكد من أثره:**

```bash
sudo docker compose down -v
```

لأنه قد يحذف Docker volumes المرتبطة بالخدمات.

**2. لا تحذف مجلد قاعدة بيانات Odoo 17:**

```text
/opt/odoo-17-docker/postgresql
```

**3. لا تحذف مجلدات بيانات PostgreSQL الخاصة بـ Odoo 19.**

**4. قبل تعديل ملفات Compose أو Entrypoint احتفظ بنسخة احتياطية.**

**5. لا تستخدم كلمة مرور ضعيفة مثل 1234 في بيئة الإنتاج.**

**6. عند تغيير كلمة مرور PostgreSQL يجب تحديث إعدادات الاتصال في خدمة Odoo المقابلة أيضاً.**

**7. احتفظ بنسخة احتياطية دورية من قواعد البيانات وملفات Odoo.**
