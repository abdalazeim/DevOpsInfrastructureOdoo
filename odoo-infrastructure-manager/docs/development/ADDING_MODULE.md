# إضافة وحدة مجال جديدة

الوحدة `apps.modules.example` هي نموذج CRUD المحايد. انسخ منها بنية البيانات والخدمة والمستودع وواجهات العرض والاختبارات أو استخدم مولّد القالب:

```powershell
python manage.py startmodule records --label "السجلات"
```

الأسماء يجب أن تكون `snake_case` بحروف إنجليزية صغيرة. يولّد الأمر الوحدة في `apps/modules/records/`، ويسجلها في `INSTALLED_APPS` ومسارات API وشريط التنقل وصفحة SPA وسكربت الصفحة، ويسجل صلاحيات العرض والإدارة والتنقل. ثم يشغّل `makemigrations` ما لم يُستخدم `--skip-migrations`.

قبل تطبيق الترحيل:

1. راجع أسماء الجداول والحقول والقيود والصلاحيات التي أنشأها الأمر.
2. ضع قواعد العمل في `services/`، والوصول إلى البيانات في `repositories/`، وابقِ الواجهات رفيعة.
3. أضف اختبارات نجاح وحدود وفشل في `tests/`.
4. شغّل `python manage.py makemigrations --check` ثم `python manage.py test apps.modules.records --settings=config.settings.test`.
5. اختبر CRUD من واجهة الويب ومن API قبل اعتماد الوحدة.

تعتمد الوحدة على `apps.core` و`apps.accounts` فقط. لا تربط وحدة بأخرى إلا عبر واجهة واضحة. احذف تسجيلاتها وواجهتها وترحيلاتها فقط بعد مراجعة بيانات قواعد الإنتاج.

## إضافة دعم المزامنة دون اتصال

إذا كانت الوحدة تحتاج Android دون اتصال، أضف `sync.py` داخل الوحدة وسجّل:

- معالجًا لكل نوع كتابة عبر `register_sync_handler(kind, callback, permission=...)`.
- مجموعة قراءة عبر `register_sync_collection(name, model=..., serializer=..., permission=...)`.
- استدعاء `register_*` من `AppConfig.ready()` بعد تسجيل صلاحيات الوحدة.

يعمل المعالج داخل معاملة يحيط بها سجل `SyncOperation`؛ استخدم `operation_id` الذي أنشأه العميل ولا تنفذ الأثر خارج هذه المعاملة. عند الحذف الصلب، أنشئ `SyncTombstone` داخل المعاملة نفسها قبل حذف العنصر. عند قبول تعديلات متزامنة، قارن `base_updated_at` بختم الخادم داخل قفل صف مناسب، وارفع `SyncConflictError` مع `model_label` و`object_pk` والطابعين والحمولة عند وجود تعارض. تراجع مشرف مخزن التعارضات في Django Admin.

المجموعة التي تسجلها هي الاسم الذي يطلبه Android عبر `SYNC_MODELS`، والنموذج يحتاج `updated_at` كي يستعمل السحب الزمني. مرر `queryset=lambda user: ...` لتقييد الصفوف حسب المؤسسة أو المستخدم، و`scope_key=lambda user: ...` كي لا تسحب المؤسسة tombstones لمؤسسة أخرى. يجب أن تطبق معالجات الكتابة النطاق نفسه قبل قراءة السجل أو تعديله أو حذفه. اختبر التكرار والمستخدم الآخر والتعارض والحذف والسحب والنطاقات المختلفة ضمن اختبارات الوحدة.
