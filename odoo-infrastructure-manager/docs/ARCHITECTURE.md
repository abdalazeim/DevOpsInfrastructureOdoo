# بنية Django Enterprise Starter

القالب تطبيق Django معياري (Modular Monolith). يحتفظ بالوحدات داخل مشروع واحد،
ويفصل مسؤوليات الحسابات والنواة ووحدات المجال من دون فرض توزيع الخدمات.

```text
config/settings/      إعدادات الأساس والتطوير والاختبار والإنتاج وسطح المكتب
apps/core/            الاستجابات، الترقيم، التدقيق، الإعدادات، الصلاحيات المشتركة
apps/accounts/        المستخدمون والأدوار والمجموعات والمصادقة
apps/modules/example/ وحدة CRUD مرجعية عامة تعمل افتراضيًا
examples/             وحدات مجال اختيارية لا تحملها الإعدادات الافتراضية
templates/             واجهة الويب وقوالب الصفحات
static/                CSS وJavaScript والأصول الثابتة
tests/                 اختبارات التكامل والعقد
deployment/            ملفات Docker وNginx وGunicorn والنشر
```

## تدفق طلب API

`config/urls.py` يركّب المسارات ذات الإصدار من `config/api_urls.py`. المصادقة
تمر عبر SimpleJWT، ثم تتحقق كل وحدة من صلاحيات المستخدم. الخدمات تتحقق من
مدخلات الوحدة وتستعمل المستودعات لعمليات البيانات. ترجع الأدوات المشتركة غلافًا
موحّدًا وتفاصيل ترقيم ثابتة.

## إضافة وحدة

أنشئ وحدة باستخدام `python manage.py startmodule <name> --label "<label>"`،
ثم سجّل تطبيقها ومساراتها وصلاحياتها صراحةً. يبدأ المثال المرجعي في
`apps/modules/example`؛ اتبع `development/ADDING_MODULE.md`.

## إعدادات التشغيل

يوضع الإعداد المشترك في `config/settings/base.py`، وتستورد البيئات الفرعية
الأساس ثم تضبط ما يخص التشغيل فقط. يجب أن يستخدم الإنتاج `production.py`؛ أما
SQLite و`development.py` فمخصصان للتطوير.
