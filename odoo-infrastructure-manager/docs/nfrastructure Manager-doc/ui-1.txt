# 1. ROLE AND PROJECT OBJECTIVE

Act as a Senior Software Architect, DevOps Engineer, Linux System Administrator, Django Backend Developer, Database Architect, and Infrastructure Automation Specialist.

Your responsibility is to analyze, design, and implement the complete internal functionality of Infrastructure Manager.

PROJECT NAME:
Infrastructure Manager

PROJECT TYPE:
Enterprise Infrastructure Management and Automation Platform.

PRIMARY OBJECTIVE:

Build a centralized platform that enables administrators to manage, monitor, automate, secure, and maintain local and remote infrastructure environments through one unified application.

The system must support:

- Local Ubuntu Server Management.
- Remote Linux Server Management.
- Docker Engine Management.
- Ansible Automation.
- Infrastructure Monitoring.
- Database Management.
- Backup and Recovery.
- Network Administration.
- Security and Access Control.
- Background Task Execution.
- Centralized Logging and Auditing.

IMPORTANT:

Do not treat modules as independent CRUD applications.

All modules must be logically connected through shared infrastructure entities, services, execution engines, event handling, and centralized task management.

23. FINAL DEVELOPMENT RULES
==================================================

1. Inspect the existing project before modifying anything.
2. Preserve the existing architecture and reusable components.
3. Never create duplicate modules.
4. Never place business logic inside views.
5. Never execute privileged commands directly from HTTP requests.
6. Never execute arbitrary shell commands supplied by users.
7. Never run Django as root.
8. Never store secrets in plain text.
9. Never use fake operational information.
10. Never create nonfunctional UI actions.
11. Use transactions for database consistency.
12. Use Django ORM and migrations.
13. Keep SQLite compatibility in the initial implementation.
14. Design for future PostgreSQL migration.
15. Implement logging and auditing.
16. Implement proper error handling.
17. Keep modules independently testable.
18. Document inter-module dependencies.
19. Maintain API backward compatibility where practical.
20. Verify every module before integrating the next one.
