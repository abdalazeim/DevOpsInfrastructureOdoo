# مراجعة إعدادات الأمان الحالية

تاريخ المراجعة: 2026-10-29. هذا ملخص إعدادات المصدر، وليس تدقيقًا اختراقيًا
ولا يثبت أمان البنية التحتية التي ستشغّل التطبيق.

## الضوابط الموجودة

- إعداد الإنتاج يرفض `DEBUG=True`، ويطلب `SECRET_KEY` و`DATABASE_URL`
  و`DJANGO_ALLOWED_HOSTS` صريحًا، ويرفض المضيف `*` ويشترط PostgreSQL.
- الإنتاج يفرض HTTPS وHSTS لمدة سنة وملفات جلسة آمنة. يبقى
  `CSRF_COOKIE_HTTPONLY=False` لأن واجهة الويب تقرأ رمز CSRF لإرساله في
  `X-CSRFToken`.
- لا تُنشأ حسابات إدارية تلقائيًا. يتطلب التهيئة الصريحة
  `DJANGO_SEED_ADMIN=True` وكلمة مرور مقدمة من البيئة.
- وحدة النقل الاختيارية خارج `INSTALLED_APPS` افتراضيًا، ولا تدخل الهجرات
  الافتراضية. راجع `examples/transport/SAMPLE.md` قبل تفعيلها.
- مشغّل سطح المكتب يستمع إلى `127.0.0.1` فقط، ويولّد مفتاح Django عشوائيًا
  ويحفظه محليًا، ولا ينشئ كلمة مرور افتراضية.
- Compose الإنتاجي لا ينشر PostgreSQL أو Redis أو Django مباشرة إلى المضيف؛
  ينشر Nginx فقط ويطلب ملفات شهادة TLS وأسرارًا صريحة.

## متطلبات قبل الإنتاج

1. استخدم أسرارًا فريدة ومدير أسرار مناسبًا للمنصة، ولا ترفع ملفات `.env`.
2. اضبط أسماء المضيفين وCSRF/CORS بما يطابق النطاقات الفعلية فقط.
3. وفّر شهادة TLS صالحة، وراجع سياسات النسخ الاحتياطي والاحتفاظ والاستعادة.
4. راجع صلاحيات الوحدات وسياسات رفع الملفات وحدود المعدل لاحتياجات المجال.
5. شغّل `python manage.py check --deploy --settings=config.settings.production`
   بعد إعداد بيئة إنتاج صالحة، ثم افحص الحاويات والتبعيات في خط النشر.

تفاصيل المصادقة والتخزين والإعدادات في `security/SECURITY.md` و
`development/SETUP.md`.
